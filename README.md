# ratchelor_djildes_version

Inspired by the desktop game, « The Ratchelor », I had as a goal to recreate the game, with the additions of elements that would include aspects of the game experience that I made up myself. Whenever I play this game, I add a bit of improvisation within it, by creating a personality to my character, and pretending that I am said character by responding orally to the different suitors. 
The main ideas of my project were then to add immersion to the game by integrating both voice and gesture input.



Concretely, the concept of the game itself is to go on dates with different characters, in order to get acclimated with them, and choosing the one who you will propose. It is composed of different rounds, each divided into two phases. The first phase of a round starts with a character talking to you, followed by your reaction. This sequence of events repeats for each of the contestants in the game. When it is over, the second phase starts. During this one, you get to choose the characters that get stay during the next phase, and the ones that are eliminated. Rounds follow each other until there is only one contestant left, the one that you choose to marry.

In order to react to dialogue while dating, and choose contestants during the elimination ceremony, you do not get to use your mouse or keyboard. The only way to interact with characters is through both voice and gestures. You can reply to them, or gesture, in order to respond. You also need to call their names when choosing who gets to stay in the competition.
For the dating phase, characters have a list of keywords associated with them. According to the ones present in your response to them, they will react differently. This is implemented in the form of an affection variable that is affected by those keywords. A suitor can react both positively, or negatively to what you have told them.

What I have been able to implement during the course of this class is the basic gameplay loop, as well as the voice input handling. The gestures handling has been scrapped because of technical issues combined with time constraints. Another aspect that has been scrapped is the possibility for a contestant to leave the competition, as it would lead to games ending prematurely depending on what the user says, and having the user not have any suitors left in the competition.

The main game has been entirely implemented within the game engine renpy, with the addition of custom Python code integrated. In particular, a game class and rat class have been implemented to the game in order to refactor the code and control the logic of the gameplay loop. All of the assets and dialogue have been created by me, mimicking the simple style of the original game. 

The input is controlled by a server, separate from the game. This has been implemented as such in order to facilitate debugging, as well as tighter error handling. The game works as client that, whenever an input is needed, requests an answer from the server, that then takes as input real time voice recording.

To use the application, you can run the bash script on linux named ‘game.sh’, that will start both the game and the server. In case of any problems, the files are also present, with the requirements, so that you can create an environment that runs the game (game_prototype.sh on linux, and game_prototype.exe on windows) and the server (audio_processing.py). When playing the game, while in the dating phase, click on the microphone in order to start speaking, as well as switch character. During the rose ceremony, you can click on the rose bouquet to start saying who you are going to give a rose to. You will not be able to go forward with going to the next round if you have not given anyone a rose, as well as given everyone a rose. Finally, to go over to the next round, you need to click on your rose bouquet and say the word final.
